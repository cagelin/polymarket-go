# Code audit review and resolution (2026-10-29)

Reviewed input: local `.local/reports/code-audit-2026-10-29.md`. See [中文版](code-audit-2026-10-29.zh-CN.md) for the detailed assessment. The original score and test results are historical observations, not evidence of the final worktree.

## Assessment

Several findings are valid, but the report overclassifies maintenance concerns and hypothetical upstream changes as P1. Public constructors should be externally usable; corrupted embedded bytecode should fail immediately; caller-controlled query mistakes should return errors. Default wallet deployment, protocol-specific parsing, and real elapsed-time budgets must retain their established contracts.

## Final agreement after two review rounds

On 2026-10-29, CodeBuddy independently reviewed the changes in its original audit conversation and issued a final verdict: **agreement reached, no remaining release blockers, and no unresolved disagreements**. Its original factual claims concerning hex decoding, injected-client timeouts, and constructor documentation were corrected. Unsupported structured error codes and unrelated contract changes are not required fixes.

Codex accepted the missing allowance-recovery negative regression and added `TestAllowanceRecoveryDoesNotRetryUnknownRejection`: unknown 400 responses preserve the rejection, submit only once, and trigger no recovery requests. Both reviewers also accepted the overlapping-selection documentation, fixed LF output, platform-independent generator input restriction, clock comment, and verification of both official CI v7 tags. CodeBuddy corrected its first-round assertions that maps necessarily allocate on the heap and that build tags would cause silent omission.

The added `BenchmarkDispatchEvent` produced these three-run medians (Go 1.27.3, darwin/arm64, Apple M1 Pro, 200ms per run):

| Scenario                    | Indexed ns/op | Original linear ns/op | Indexed B/op / allocs |
|-----------------------------|--------------:|----------------------:|----------------------:|
| 1 subscription, one match   |         107.3 |                 30.24 |                48 / 2 |
| 8 subscriptions, one match  |         107.1 |                 127.2 |                48 / 2 |
| 64 subscriptions, one match |         110.4 |                  1626 |                48 / 2 |
| 64 subscriptions, all match |          4604 |                  2131 |             4504 / 11 |

The linear reference allocates 0 B/op in these cases. The small candidate-set deduplication map does not escape; the fixed 48 B/two allocations come from event-key slices and appending the wildcard key. Indexing is not universally faster: small subscriptions and full fanout retain a measured cost, recorded as optional optimization work. These isolated dispatch measurements exclude JSON, networking, and competing goroutines; they do not measure live throughput or lock-contention benefits. CodeBuddy independently reproduced comparable results and accepted these limits.

After the second-round additions, `make check` passed and cross-package coverage remained **83.9%**. Neither party committed, pushed, or performed real-account actions. Remote CI has not run. Review agreement is not deployment or commit authorization.
